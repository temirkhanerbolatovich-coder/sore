# Как работать над Sөre

Короткие правила для команды. Запуск проекта: [docs/ONBOARDING.md](docs/ONBOARDING.md). Карта кода: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Ветки

| Ветка | Назначение |
|---|---|
| `main` | боевая. Каждый коммит сюда Vercel сам выкладывает на сайт. Только релиз через PR из `develop` |
| `develop` | интеграция. Сюда сливаются все PR с работой |
| `тип/кратко` | рабочие ветки от `develop`: `feat/bot-login`, `fix/import-limit`, `docs/onboarding`, `chore/deps` |

Прямых пушей в `main` и `develop` нет, только через PR. Защита веток средствами GitHub на бесплатном плане приватного репозитория недоступна, поэтому правило держится на договорённости и на CI. Ветки удаляются после слияния автоматически.

## Коммиты

На русском, в формате `тип(область): суть`:

`feat(shelf): …` новая возможность · `fix(import): …` исправление · `docs: …` документация · `test(e2e): …` тесты · `chore(deps): …` зависимости и служебное · `ci: …` CI.

Один коммит на одну мысль. Подробности (почему и что проверено) в теле коммита.

## Pull request

1. Ветка от свежего `develop`, небольшой PR на одну задачу (лучше 300 строк, чем 3000).
2. Заполните шаблон PR: что менялось, как проверить, что не проверено.
3. Перед PR локально: `npm run lint`, `npx next typegen && npm run typecheck`, `npm test`; при правках SQL `npm run test:rls`; при правках интерфейса `npm run build && npm run test:e2e`.
4. CI на GitHub (`secrets`, `verify`) должен быть зелёным. Красный CI не сливаем, чиним причину (а не ослабляем тест).
5. Слияние в `develop`: кнопка «Merge pull request» (merge commit) или «Squash and merge» для мелких веток. Ветку после слияния GitHub удалит сам.
6. Релиз: PR `develop` → `main` с описанием, что вошло. Сливает владелец репозитория (Vercel на бесплатном плане деплоит только коммиты владельца).

## Правила кода

- **Цвета только через токены** (`src/app/globals.css`, светлая и тёмная тема), без `#hex` в компонентах. Иконки только из `src/components/icons.tsx`. Анимируем `transform` и `opacity`, учитываем `prefers-reduced-motion`.
- **Интерфейс mobile-first** (проверяйте 360 и 390 px), кнопки не ниже 44 px, обе темы.
- **Миграции:** применённые (`0001`–`0018` и далее после выкладки) не редактируются, изменения только новым файлом `NNNN_название.sql` с RLS и тестом в `supabase/tests/rls.sql`.
- **Цены, лимиты и квоты** решает база (функции Postgres), а не браузер.
- **Секреты** (ключи, токены, пароли) никогда не попадают в git, логи, скриншоты и чат. Только переменные окружения. `.env.local` в `.gitignore`.
- **Новые зависимости** только при необходимости, с записью в [docs/DECISIONS.md](docs/DECISIONS.md) (зачем, размер, лицензия).
- **Next.js 16** отличается от привычных версий: перед правкой маршрутов, кэша и middleware (`src/proxy.ts`) читайте документацию из `node_modules/next/dist/docs/` (см. `AGENTS.md`).

## Задачи

Ведём в [Issues](https://github.com/temirkhanerbolatovich-coder/sore/issues). Метки:

- область: `area:bot`, `area:shelf`, `area:import`, `area:design`, `area:email`, `area:infra`, `area:docs`;
- приоритет: `priority:p0` (блокирует запуск), `priority:p1`, `priority:p2`;
- статус: `status:blocked`, `status:needs-decision` (ждёт решения владельца продукта).

Вехи: **Запуск (MVP)** и **Telegram-бот**. Берёте задачу: назначьте на себя и напишите в комментарии, с какой ветки начинаете.
