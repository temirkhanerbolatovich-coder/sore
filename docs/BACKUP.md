# Резервные копии базы

На бесплатном тарифе Supabase своих резервных копий нет (они появляются на Pro). Пока денег на Pro нет, копии делает GitHub Actions: [.github/workflows/backup.yml](../.github/workflows/backup.yml).

## Что и как

- Раз в неделю (воскресенье, 03:00 UTC) и по кнопке («Run workflow») делается логическая копия схем `public` (магазины, товары, заказы) и `auth` (пользователи) командой `pg_dump` версии 17, как у сервера.
- Копия шифруется (GPG, AES-256) фразой `BACKUP_PASSPHRASE` и сохраняется как артефакт запуска на 90 дней: GitHub → Actions → «Резервная копия базы» → запуск → Artifacts → `sore-db-backup`.
- Запрос к базе заодно не даёт проекту «заснуть» из-за недельной тишины.

**Что не копируется:** файлы в Storage (фото товаров). Supabase их не включает в копии базы. Потерянные фото восстановить нельзя, поэтому уборка осиротевших фото осторожная (см. DEPLOY.md). Если фото критичны, раз в месяц выгружайте бакет `product-photos` вручную.

## Настроить один раз

1. GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret:
   - `SUPABASE_DB_URL`: адрес подключения к базе. Supabase → Project Settings → Database → Connection string → **Session pooler** (порт 5432), подставьте пароль базы. Вид: `postgresql://postgres.<ref>:<пароль>@aws-0-eu-central-1.pooler.supabase.com:5432/postgres`.
   - `BACKUP_PASSPHRASE`: длинная случайная фраза (30+ символов). **Сохраните её отдельно** (менеджер паролей): без неё копию не расшифровать.
2. Actions → «Резервная копия базы» → Run workflow. Проверьте, что артефакт появился.

Копия содержит данные продавцов и покупателей (телефоны, адреса): держите расшифрованные файлы только на своём компьютере и не отправляйте их в чаты.

## Восстановление

```bash
# 1. Скачайте артефакт, распакуйте, расшифруйте
gpg --batch --pinentry-mode loopback --decrypt --passphrase "ВАША_ФРАЗА" -o sore.dump sore-YYYY-MM-DD.dump.gpg

# 2. Посмотрите, что внутри (без записи в базу)
pg_restore --list sore.dump | head

# 3. Восстановите в ПУСТОЙ проект Supabase (не в боевой поверх живых данных!)
pg_restore --no-owner --no-privileges --clean --if-exists --dbname "postgresql://…" sore.dump
```

Перед восстановлением создайте проект, примените миграции (`supabase db push`), затем загрузите данные. Пробуйте восстановление на тестовом проекте минимум раз: непроверенная копия копией не считается.
