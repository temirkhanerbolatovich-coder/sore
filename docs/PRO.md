# Тариф Pro: ручное подключение

Pro стоит 2 500 ₸ в месяц и снимает ограничения Free: до **500 товаров** (вместо 15) и **100 ИИ-запросов в сутки** (вместо 20). Оплата пока вручную, без эквайринга.

## Как это работает

1. В кабинете продавца карточка «Pro · 2 500 ₸ в месяц» и кнопка «Снять ограничения» (она же в предупреждении о лимите товаров). Кнопка открывает WhatsApp владельца с готовым текстом и адресом магазина.
2. Клиент переводит деньги (Kaspi или счёт ИП) и присылает чек.
3. Владелец включает Pro командой (из корня репозитория, в терминале с ключом службы облачной базы):

```bash
npm run plan -- <адрес-магазина> 30 --allow-remote
```

Повторный вызов продлевает срок: если Pro ещё действует, 30 дней прибавляются к его концу, иначе отсчёт идёт от сегодня.

| Команда | Что делает |
|---|---|
| `npm run plan -- adres 30 --allow-remote` | включить или продлить на 30 дней |
| `npm run plan -- adres --off --allow-remote` | вернуть Free сразу |
| `npm run plan -- --list --allow-remote` | все магазины с действующим Pro и сроками |

Скрипту нужны `NEXT_PUBLIC_SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` облачного проекта в окружении терминала (в `.env.local` указана локальная база).

## Что происходит по окончании срока

Pro гаснет сам (сравнение `pro_until > now()` в базе и в приложении). Магазин возвращается на Free: уже добавленные товары остаются и видны покупателям, но новые сверх 15 добавить нельзя, ИИ-квота снова 20. Продавец видит обычную карточку с кнопкой «Снять ограничения». За 7 дней до конца карточка Pro предлагает продлить.

## Где это устроено

- `supabase/migrations/0027_pro_plan.sql`: столбец `shops.pro_until` (продавец менять не может: нет в `grant update`), функция `private.shop_product_limit`, триггер лимита товаров.
- `src/lib/types.ts`: `PRO_PRODUCT_LIMIT`, `PRO_AI_DAILY_LIMIT`, `isPro`, `productLimit`. ИИ-квота выбирается в `src/lib/ai-request.ts`.
- `src/lib/support.ts`: ссылка WhatsApp. Номер задаётся `NEXT_PUBLIC_SUPPORT_WHATSAPP` (только цифры) в Netlify; без неё кнопки не показываются.
- Не забудьте: после смены `NEXT_PUBLIC_*` нужен новый деплой.

## Порядок выкладки

Миграцию `0027` на облако применяют **до** релиза в `main` (`npx supabase db push --remote`), потом переменная `NEXT_PUBLIC_SUPPORT_WHATSAPP` в Netlify, потом релиз.
