## 1. Критично: сделать до приёма реальных продавцов

### 1.1 Реальные ключи ИИ лежат в `.env.example` и в истории git

**Что нашёл.** В `.env.example` (в `HEAD`, на GitHub в ветках `master` и `feat/mvp-foundation`) были значения `GEMINI_API_KEY` и `OPENROUTER_API_KEY`. Ключ OpenRouter совпадает с рабочим из `.env.local`. Старые коммиты (`dbe170a`, `79b80c2`, `73ed133`, `2dfa933`) содержат те же значения. Репозиторий приватный, поэтому утечки наружу нет, но ключи видят все, у кого есть доступ к репозиторию, и они навсегда остаются в истории.

**Уже сделано.** В рабочей копии значения заменены на пустые (`GEMINI_API_KEY=`, `OPENROUTER_API_KEY=`). Правка пока не закоммичена.

**Что нужно.**
1. Перевыпустить оба ключа: Google AI Studio (https://aistudio.google.com/apikey) и OpenRouter (https://openrouter.ai/keys), старые удалить.
2. Положить новые в Vercel (Production) и в `.env.local`. Вставлять их надо в своём терминале, не в чат.
3. Закоммитить исправленный `.env.example`.
4. Переписывать историю git не нужно: после отзыва старые ключи ничего не открывают.

**Профилактика.** Включить Secret scanning на GitHub (для приватных репозиториев нужен платный план, для публичных бесплатно) или поставить `gitleaks` в CI и в pre-commit.

### 1.2 Нет защитных заголовков

Сайт отдаёт только `Strict-Transport-Security`. Нет `Content-Security-Policy`, `X-Frame-Options`/`frame-ancestors`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`. Самое важное: кабинет можно встроить в чужую страницу (кликджекинг), а любая XSS не ограничена политикой.

**Что делать.** Добавить `headers()` в `next.config.ts`:
- `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, `frame-ancestors 'none'`.
- CSP сначала в режиме `Content-Security-Policy-Report-Only`, неделю смотреть нарушения, потом включить. Разрешить: `self`; скрипты и подключения Vercel Analytics/Speed Insights; `*.supabase.co` для `connect-src` и `img-src`; `data:` и `blob:` для картинок (сжатие фото на телефоне).
- Размер: S (полдня с проверкой E2E).

### 1.3 Функции Vercel в США, база во Франкфурте

В ответе `X-Vercel-Id: fra1::iad1::…` вторая часть (`iad1`) — это Вашингтон. База Supabase в `eu-central-1` (Франкфурт), покупатели в Казахстане. Каждый запрос витрины идёт Франкфурт → США → Франкфурт, и это повторяется для каждого из двух запросов к базе.

**Что делать.** Файл `vercel.json` с `{"regions": ["fra1"]}` (или настройка региона функций в панели проекта). Ожидаемый эффект: время ответа сервера упадёт заметно (оценка: с ~0,55 с до ~0,15–0,25 с). Размер: S, 10 минут.

### 1.4 Витрина не кэшируется, плюс «мягкие» 404

**Факты.**
- `Cache-Control: private, no-cache, no-store` у `/povar-astana`. Страница динамическая, потому что данные читаются клиентом Supabase с куками (`createClient()` из `server.ts`), хотя витрина публичная.
- Несуществующий магазин `/no-such-shop-xyz` и товар `/povar-astana/p/000…` отвечают **200**, не 404. Причина описана в документации Next.js: `loading.tsx` начинает стрим раньше, чем срабатывает `notFound()`, и статус уже не изменить (добавляется только `noindex`).
- Из-за `no-store` страница не попадает в bfcache (мгновенная кнопка «Назад» в браузере).
- Из-за стрима `<meta name="description">` оказывается в теле документа, и Lighthouse считает его отсутствующим.

**Что делать.**
1. Для публичных данных витрины завести отдельного клиента Supabase **без кук** (анонимный ключ) и кэшировать выборку через Cache Components / `use cache` (в этой версии Next.js есть, см. `node_modules/next/dist/docs/01-app/01-getting-started/08-caching.md`) с тегом на магазин, например `shop:{slug}`.
2. В действиях кабинета, где уже есть `revalidatePath`, добавить сброс тега, чтобы изменения продавца появлялись сразу.
3. Проверку «магазин существует» вынести в `src/app/[slug]/layout.tsx` (он выше границы `loading.tsx`): тогда `notFound()` отдаст честный 404. Для товара: 404 сразу, если товара нет в кэшированном списке.
4. После этого проверить, что корзина и счётчик просмотров по-прежнему работают (они клиентские).
- Размер: M (1–2 дня с тестами). Ожидаемый эффект: ответ из кэша за десятки миллисекунд, нагрузка на базу падает на порядок, Lighthouse SEO 100.

### 1.5 Заказы можно засыпать спамом

`create_order` ограничивает только `по телефону` (10 заказов в час на номер). Номер можно менять, поэтому злоумышленник за минуты создаст сотни «заказов» в чужой магазин, каждый уйдёт продавцу в Telegram и забьёт список.

**Что делать.**
- В `create_order` добавить лимит на магазин (например, 30 заказов в час; всплеск выше порога сигнализирует о спаме) и мягкую блокировку с понятным сообщением для покупателя.
- Скрытое поле-ловушка (honeypot) и минимальное время заполнения формы.
- При необходимости Cloudflare Turnstile (бесплатно, без капчи для людей) на шаге «Заказать».
- Размер: S–M.

## 4. Безопасность: подробно

**Что в порядке (проверено).**
- RLS включён на всех таблицах, права `anon`/`authenticated` урезаны до нужных столбцов, служебные функции в схеме `private`. 41 проверка в `supabase/tests/rls.sql`.
- Функции `SECURITY DEFINER` с `search_path = ''`; заказ считается на сервере по актуальным ценам, а не по цене из корзины.
- Секреты Telegram (`/api/telegram/webhook`, `/api/telegram/notify`) закрыты (запрос без секрета → 403), сравнение через `timingSafeEqual`. ИИ-маршрут без входа → 401.
- Путь к фото проверяется на принадлежность владельцу (`ownedPhotoPath`), нет обхода папок и чужих источников.
- `/auth/callback` не принимает параметр перенаправления: открытого редиректа нет. Выход из аккаунта только POST.
- `npm audit`: 0 уязвимостей. В истории git нет паролей базы, токенов Telegram и секретов Google; единственная проблема — ключи ИИ (п. 1.1).

**Что улучшить.**

## 7. Модернизация (что даёт Next.js 16 и экосистема)

- **Cache Components / `use cache` и теги** — основа п. 1.4: витрина статична, обновляется по событию.
- **Частичная предварительная отрисовка**: оболочка витрины мгновенная, динамические части (корзина, счётчик) дорисовываются. Это заодно убирает «мигание» `loading.tsx`.
- **`next/image` или собственные миниатюры** (п. 2.3). Оптимизатор Vercel на Hobby ограничен по числу картинок, поэтому надёжнее своё превью, полученное на телефоне при загрузке; Supabase Image Transformations доступны на платных тарифах.
- **PWA для кабинета**: установка на главный экран, офлайн-страница, Web Push.
- **Типизированные переменные окружения** (п. 4.7) и единая карта «какая переменная где обязательна».
- **Генерация типов базы** (`supabase gen types`) в CI с проверкой, что файл не разошёлся с миграциями.
- **Журнал ошибок и трассировки** на Vercel Observability + Sentry.

## 8. Рекомендуемый порядок

**Шаг 0 — сегодня, 1–2 часа (в основном действия владельца).**
1. Перевыпустить ключи Gemini и OpenRouter, обновить Vercel и `.env.local` (п. 1.1); закоммитить `.env.example`.
2. Регион функций `fra1` (п. 1.3).
3. Защитные заголовки, CSP сначала в режиме отчётов (п. 1.2).
4. Включить 2FA на всех сервисах (п. 4.8).
5. Убрать хвосты: удалить три файла `client_secret_*.json` из «Загрузок», лишний клиент Google, вернуть «Повар на выезд» в режим «От», отменить тестовый заказ №1, включить Analytics и Speed Insights в Vercel.

**Шаг 1 — 2–3 дня: скорость и честные страницы.**
Кэш витрины с тегами, 404 через `layout.tsx`, `lazy`/`fetchpriority`, подложки, миниатюры (п. 1.4, 2.2–2.4). Цель Lighthouse по витрине: производительность ≥ 90, SEO 100, LCP ≤ 2,5 с. Заодно JSON-LD и товары в sitemap.

**Шаг 2 — 2 дня: устойчивость.**
Лимит на магазин и защита формы заказа (п. 1.5), лимит `report-error` (п. 4.1), очистка служебных таблиц и глобальный потолок ИИ (4.2, 4.3), резервные копии и решение по тарифу Supabase (1.6).

**Шаг 3 — 1–2 недели: то, что видят продавец и покупатель.**
Галерея, «О магазине», поиск, статус заказа, поиск и экспорт заказов, Web Push, QR-плакат (5.2, 5.3, 5.4, 5.5, 5.13, 5.14, 5.11).

**Шаг 4 — после своего домена (отложено по решению владельца).**
Своя почта и вход по коду, публикация приложения Google без лимита в 100 человек, тарифы Pro, отдельное тестовое окружение, перевод интерфейса на казахский.
