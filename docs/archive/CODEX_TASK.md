## 1. Что такое DukenAI

Мобильный конструктор магазина-ссылки для микропродавцов Казахстана. Продавец фотографирует товар, ИИ пишет карточку (название, описание RU + KZ, категория), клиент открывает `duken.ai/<slug>` без регистрации, собирает корзину и жмёт «Заказать в WhatsApp». Заказ сначала сохраняется в базе, затем открывается `wa.me` с готовым текстом.

Целевая аудитория: домашние кондитеры Алматы, хендмейд, цветы. Пользователи работают с телефона. Язык интерфейса: русский, описания товаров на русском и казахском.

## 2. Правила работы

1. Прочитай `AGENTS.md` и нужные разделы в `node_modules/next/dist/docs/` перед правками. Это **Next.js 16**: `middleware` теперь `src/proxy.ts`, `params` и `searchParams` асинхронные (`Promise`), для типов есть глобальный `LayoutProps`/`PageProps`. Не пиши по памяти старых версий.
2. Стек менять нельзя: Next.js App Router, TypeScript, Tailwind v4, Supabase (Postgres, Auth, Storage), Zustand, zod, `@anthropic-ai/sdk`.
3. Существующие миграции `supabase/migrations/0001`–`0005` **не редактируй**. Любые изменения схемы только новыми файлами `0006_*.sql` и дальше.
4. Работай в ветке `feat/mvp-foundation`. Делай небольшие коммиты с понятными сообщениями на русском.
5. Секреты (`ANTHROPIC_API_KEY`, ключи Supabase) никогда не попадают в клиентский код и в git. Файл `.env.local` в `.gitignore`.
6. Перед каждым коммитом: `npm run lint && npm run build` без ошибок.
7. Не добавляй то, что вне скоупа: онлайн-оплату и Kaspi, WhatsApp-бота, подсказку цены по фото, варианты товара, биллинг, нативное приложение.

## 4a. Что нужно сделать в первую очередь (P0)

### P0.1. Поднять проект и прогнать весь путь

1. Создай `.env.local` по `.env.example`. Если ключей Supabase нет, подними локально через Supabase CLI (`supabase start`) и подставь локальные ключи. Применить миграции по порядку и `seed.sql`.
2. Для демо-аккаунта создай пользователя `demo@duken.ai` (в локальном Supabase через Studio или Admin API).
3. Пройди вручную (через Playwright, см. P1.1) весь путь и почини всё, что сломалось:
   вход → создание магазина → новый товар с фото → «Заполнить с ИИ» → витрина → корзина → заказ → ссылка `wa.me` → заказ в `/dashboard/orders` → статистика.
4. Если нет `ANTHROPIC_API_KEY`, проверь ИИ-роут с подменой клиента Anthropic в тесте и убедись, что без ключа форма не ломается (503 и понятное сообщение).

Критерии: на чистой базе путь выше проходит без ошибок в консоли и сервере.

### P0.2. Аудит безопасности и RLS

Напиши SQL-тесты или скрипт (`supabase/tests/rls.sql` или Playwright/Vitest с двумя пользователями) и докажи:

- аноним читает только `shops` и `products`, не читает `orders`, `events`, `ai_generations`;
- аноним может вызвать `create_order`, но не может сам делать `insert` в `orders` (прямую вставку закрывает миграция `0005_close_direct_order_insert.sql`, проверь, что это действительно так и что оформление заказа через `rpc` по-прежнему работает);
- пользователь A не меняет и не читает магазин, товары, заказы пользователя B;
- в Storage нельзя писать в чужую папку `<user_id>/`;
- `create_order` отклоняет: пустую корзину, количество вне 1–99, товар не из этого магазина, товар не в наличии, плохой телефон;
- `events` и `create_order` защищены от флуда (см. P1.4).

Найденные дыры чини миграциями `0006_*`.

### P1.2. Настройки магазина (вернуть вкладку «Магазин»)

### P1.3. Корректность корзины и заказа

- Корзина хранит цену на момент добавления. Если продавец поменял цену или товар закончился, при открытии `/[slug]/cart` сверяй со свежими данными с сервера: обнови цены, убери недоступное, покажи понятное сообщение.
- Если `create_order` отклонил заказ, различай причины (товара нет в наличии и прочее) и пиши об этом человеческим текстом.
- Перевод интерфейса корзины, оформления и экрана «Заказ принят» на казахский при `?lang=kz` (словарь в `src/lib/lang.ts`). Текст сообщения в WhatsApp остаётся русским: его читает продавец.
- Номер заказа сейчас сквозной по всей системе. Сделай нумерацию внутри магазина (№1, №2…) новой миграцией, без поломки существующих заказов.
- Сохрани имя и телефон клиента в `localStorage`, чтобы не вводить заново (с возможностью очистки).

### P1.4. Защита от злоупотреблений

- Лимит на публичные вставки: не больше N событий `view` с одного клиента в минуту и разумный лимит `create_order` (например, 10 заказов в час с одного IP или телефона). Реализуй в SQL (триггер или проверка в функции) или через route handler + таблицу счётчиков. Опиши выбор в `docs/DECISIONS.md`.

- ИИ-роут: ограничь размер и тип фото, проверь, что файл реально лежит в папке пользователя (уже есть проверка префикса, добавь тест).

## 6. Ограничения и подводные камни

- Телефон WhatsApp хранится только цифрами в международном формате (`77011234567`). Не ломай `normalizePhone`.
- Корзина привязана к одному магазину, при смене магазина сбрасывается. Гидратацию делай через `useHydrated` (иначе будет рассинхрон SSR и клиента).
- `create_order` считает цены на сервере. Нельзя доверять ценам из браузера, не ослабляй это.
- Витрина `/[slug]` не должна конфликтовать со статическими маршрутами: `login`, `dashboard`, `auth`, `api`, `demo` в `RESERVED_SLUGS` в `src/lib/slug.ts`. Добавляя маршрут верхнего уровня, добавь его туда же.
- Описание ИИ не должно содержать выдуманных фактов о составе, весе и размере. Не меняй промпт в `src/lib/ai-card.ts` в сторону большей «фантазии».
