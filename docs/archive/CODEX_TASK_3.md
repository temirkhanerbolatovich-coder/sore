## 4. Стадия B. «Фото полки → много товаров» (обязательная)

Главная новая функция. Продавец загружает **одно** фото полки или витрины, ИИ находит до 12 товаров, для каждого даёт карточку и вырезку, продавец правит черновики и публикует выбранные.

**B1. Схема (миграция `0016_shelf_mode.sql`).** В `products` добавь, все nullable или с безопасным default: `bbox jsonb` (объект `{x1,y1,x2,y2}`, числа 0..1, `x1<x2`, `y1<y2`; проверка через функцию `valid_bbox`, по образцу `valid_variants`), `source_photo_url text` (фото полки, из которого вырезан товар), `sku text` (до 100 символов), `price_needs_review boolean not null default false`. Уникальный частичный индекс `(shop_id, sku) where sku is not null`. Ограничения длины в духе `0008_input_constraints.sql`. RLS не ослабляй. Добавь тесты в `supabase/tests/rls.sql`: чужой продавец не видит и не меняет поля, невалидный `bbox` отвергается, дубль `sku` в одном магазине отвергается, в разных можно.

**B2. ИИ-распознавание (`src/lib/ai-shelf.ts` + расширение `src/lib/ai-providers.ts`).** Функция `generateShelf(image)` возвращает `{ items: ShelfItem[], provider }`, где `ShelfItem = { title, description_ru, description_kz, category, bbox, price_hint? }`.
- Схема ответа валидируется zod: не больше 12 товаров, `bbox` обрезается в 0..1, отбрасываются рамки с площадью < 1% кадра или вырожденные, дубли (IoU > 0.6) схлопываются.
- Правила промпта те же, что у `buildSystemPrompt` (ничего не выдумывать: состав, вес, цену, «домашний»), плюс: рамка по видимому товару, не больше одной рамки на товар, **цену не оценивать**. `price_hint` заполняется только если цена видна на ценнике на фото. Такие цены помечаются `price_needs_review`.
- Цепочка провайдеров та же (gemini → openrouter → anthropic), провайдер без ключа пропускается. Если ни один провайдер не вернул валидный список, API отвечает понятной ошибкой и предлагает режим «одна карточка».
- Юнит-тесты: разбор валидного ответа, обрезка рамок, дубли, мусорный JSON, пустой список, более 12 товаров.

**B3. Маршрут `POST /api/ai/shelf`.** По образцу `api/ai/product-card/route.ts`: авторизация, принадлежность фото пользователю (`ownedPhotoPath`), размер и тип, **суточные лимиты и `reserve_ai` расходуются один раз на фото полки** (не на каждый товар), `maxDuration` ≤ 60, общий таймаут цепочки. Ответ содержит черновики без записи в таблицу `products`. Запись только после подтверждения продавцом (B5). Не допускай расхода ИИ неавторизованными пользователями и повторных вызовов на один и тот же файл (идемпотентность по хэшу, если это просто делается, иначе опиши ограничение).

**B4. Вырезки (`src/lib/shelf-crops.ts`).** На сервере через `sharp` (уже в devDependencies; если нужен в `dependencies` для production, перенеси и запиши в `DECISIONS.md`) для каждой рамки: небольшой отступ (6%), квадрат до 600×600, WebP, загрузка в бакет `product-photos` по пути `<user_id>/…` с соблюдением ограничений бакета (5 МБ, mime). Если вырезка не удалась, товар остаётся без своей фотографии и показывает фото полки. Вырезки удаляются вместе с товаром, как уже сделано для миниатюр (`regressions.spec.ts`, «Storage очищается»). Утечек файлов быть не должно.

**B5. Экран «Фото полки» в кабинете (`/dashboard/products/shelf`).**
- Вход: кнопка рядом с «Добавить сразу несколько фото» на главной кабинета. Одно фото, превью, понятный прогресс («Ищем товары на полке…»), отмена.
- Результат: сетка черновиков (вырезка, название, цена, категория, галочка «публиковать»). Все поля редактируются, пустая цена допустима только как «Цена по запросу» через существующий режим цен (`0009_price_modes.sql`). Кнопка «Опубликовать выбранные (N)» → server action с пачечной вставкой **под лимит `FREE_PRODUCT_LIMIT`**: лишние отбрасываются с понятным сообщением, а не падают.
- Обработка ошибок: ИИ не настроен, ИИ ничего не нашёл, лимит исчерпан, сеть пропала. Всегда есть путь назад и ручное добавление.
- Анимации: черновики появляются через `rise-in`, иконки из `icons.tsx`. Обе темы.
- Витрина: в карточке товара из режима полки показывается фото полки с рамкой (как делает «Витрина»: SVG-рамка поверх изображения, размер берётся из реальных ширины и высоты, без CLS). Если `source_photo_url` пусто, ничего лишнего не показывается.
- После публикации сбрось теги кэша витрины так же, как остальные действия продавца (см. B1 из задания №2).

**B6. Тесты стадии.** e2e с подменой `/api/ai/shelf` (3–5 товаров): загрузка → черновики → правка → публикация → товары видны на витрине и в кабинете, рамка есть; публикация сверх лимита; ИИ вернул пусто; без входа 401. Юнит-тесты B2. RLS-тесты B1. Размер страницы витрины не растёт больше чем на 3 КБ JS.

## 5. Стадия C. Импорт каталога из Excel/CSV (обязательная)

Низкий порог входа для тех, у кого уже есть прайс. Только веб-кабинет (бот потом подключится к тем же функциям).

**C1. Разбор файла (`src/lib/catalog-file.ts`).** Форматы `.xlsx` и `.csv`. Для xlsx допустим один пакет (рекомендуется `exceljs` или более лёгкий, выбор обоснуй в `DECISIONS.md`). Колонки: `name`, `price_kzt` обязательны; `quantity`, `category`, `sku`, `description`, `name_kk` по желанию. Принимай русские и казахские заголовки («Название», «Цена», «Количество», «Категория», «Артикул», «Описание»; «Атауы», «Баға») без учёта регистра и лишних пробелов. Цена «1 500,50 ₸» → 1501; неразрывные пробелы, «тг», «₸». CSV: разделитель `;`, `,` или табуляция, UTF-8 и Windows-1251, RFC 4180. Каждая строка проверяется zod; ошибка строки **не останавливает** импорт. Категории сопоставляются со словарём Sөре (см. `DEFAULT_CATEGORIES` в `ai-card.ts`), незнакомые → «Другое».
- Защита: файл ≤ 4 МБ, строк ≤ 2000; для xlsx **проверь размер после распаковки** (zip-бомба) до чтения листа и читай потоково, если пакет это умеет. Макросы и внешние ссылки игнорируются. Ошибку формата файла показывай человеческим текстом, `.xls` отклоняй с подсказкой «сохраните как .xlsx».
- Юнит-тесты: заголовки, числа, CSV в разных кодировках, пустые и битые строки, лимиты, дубль `sku` в файле (побеждает последняя строка, первая попадает в отчёт).

**C2. Запись (server action, от имени продавца, не через service role).** Пачки по 200 строк. Upsert по `(shop_id, sku)`: повторная загрузка того же файла **обновляет** товары, а не дублирует; строка без `sku` всегда создаёт новый товар. Пустые поля файла не затирают данные, которые продавец уже ввёл. **Тарифный лимит `FREE_PRODUCT_LIMIT` соблюдается**: новые строки сверх оставшихся мест попадают в отчёт с причиной «лимит тарифа», обновление существующих разрешено. Одновременный второй импорт того же магазина блокируется понятным сообщением.

**C3. Экран «Загрузить прайс» (`/dashboard/products/import`).** Выбор файла, шаблон для скачивания (xlsx или csv с примером двух строк, на русском и казахском), прогресс, итог «Загружено N, обновлено M, пропущено K», кнопка «Скачать отчёт об ошибках» (CSV для Excel: BOM, `;`, номера строк и причины). Анимации и иконки из общего набора, обе темы, 360 px.

**C4. Тесты.** e2e: шаблон → заполненный файл → импорт → товары на витрине; повторная загрузка не дублирует; файл с ошибками даёт отчёт; сверх лимита; чужие данные недоступны. Фикстуры лежат в `tests/fixtures/` (небольшие, без персональных данных).
